Render OG images
in CI, not in prod

og-image-action bakes your 1200×630 social-share image into the build — once, in the workflow that already builds your site. No hosted API to call, no account to create, no server to keep running. Add one step to your workflow YAML. That's the whole integration.

MIT licensed · github.com/nagpalarpit/og-image-action@v1 · zero runtime dependency

Add it to a workflow

Drop this into any job that builds your site — right before you publish. It writes a PNG to the path you give it; commit it, upload it as a build artifact, or let your deploy step pick it up like any other static file. 

- uses: nagpalarpit/og-image-action@v1
  with:
    title: 'How We Cut Cold-Start Latency by 80%'
    description: 'A deep dive into Workers, D1, and request coalescing.'
    theme: dark
    template: blog
    author: 'Jane Doe'
    domain: example.com
    tag: Engineering
    output-path: public/og/how-we-cut-cold-start-latency.png

Only title is required — everything else has a sane default.

Build-time vs. runtime — not a rematch

● og-image-action (this)

Renders once, in CI, for content you already know at build time — a blog post, a docs page, a release. The output is a static PNG sitting next to the rest of your build. Nothing runs at request time. Best for static sites, blogs, and docs.

vs

● SnapOG (hosted API)

Renders per request, at the edge, cached — for content you don't control ahead of time: user-generated pages, a CMS you don't own the build for, anything where the title isn't known until someone asks for it.

Same rendering stack under the hood — Satori + resvg — just invoked at a different point in the pipeline. Read the full write-up →

How it works

01

Add the step

One entry in your existing build workflow. No new pipeline, no npm publish.

02

Satori + resvg render it

Layout via Satori, rasterized to PNG by @resvg/resvg-js — inside the action's node20 runtime, no network calls.

03

Ship it as a static file

The PNG lands at your output path. Commit it or let your existing deploy step publish it — same as any other asset.
